## 修复终端粘贴内容重复两份的问题

- 文件：`src/components/terminal/useTerminalManager.ts`
- 根因：`term.attachCustomKeyEventHandler` 返回 `false` 只会跳过 xterm 自身的 keydown 处理，但**不会**自动调用 `event.preventDefault()`。因此浏览器仍会在 xterm textarea 上触发原生 `paste` 事件，xterm 内部的 paste 监听器读取 `clipboardData` 又粘贴一次，叠加手动的 `readText()` + `term.paste(text)`，导致粘贴内容出现两份。
- 修复：在拦截 Cmd/Ctrl+V 时显式调用 `event.preventDefault()` 阻断原生 paste 路径，仅保留手动的一次 `term.paste()`。
- 验证：`tsc --noEmit -p tsconfig.app.json` 通过，无类型错误。

## 修复块工具栏导航键 + NodeView 误选中 bug

两个问题一并修复：

### 1. BlockToolbar 左右箭头切换 → 仅 Tab 切换
- 文件：`src/components/editor/hooks/useNodeToolbarNav.ts`
- 原状：选中节点后 Tab/Shift+Tab **和** ArrowLeft/ArrowRight 都能循环切换工具栏按钮。
- 改为：仅 Tab/Shift+Tab 循环按钮；ArrowLeft/ArrowRight 直接放行给 ProseMirror（让光标从 NodeSelection 自然移出到相邻文本）。

### 2. 文本选区扫过图片/文件块时错误高亮（"时序图片也被选中"）
- 根因：`ImageView` / `FileView` 直接用 TipTap 的 `NodeViewProps.selected` prop。该 prop 在**选区范围包含该节点**时就为 true（包括拖选/Shift+方向键扫过的文本选区），导致用户选中上方句子时下方图片也亮起工具栏/选中环。
- `DiagramBlockView` 早已用内联的 `selectionUpdate` + `NodeSelection` 判定绕开此问题。
- 修复：把 DiagramBlockView 的判定逻辑抽成可复用 hook `src/components/editor/hooks/useNodeSelected.ts`（仅当 `sel instanceof NodeSelection && sel.from === pos` 才返回 true）。`ImageView`、`FileView`、`DiagramBlockView` 三者统一改用该 hook。
- 验证：`npx tsc --noEmit` 通过。
- 注意：LinkView 用的是自管 `isSelected` 状态（点击切换），不走 PM NodeSelection，不受此影响。

## 修复代码块粘贴卡顿（增量 Lowlight 插件）

- 现象：在代码块里粘贴大段代码会卡顿一下。
- 根因：`@tiptap/extension-code-block-lowlight` 内置的 `LowlightPlugin.apply`（`node_modules/@tiptap/extension-code-block-lowlight/dist/index.js` 第 75-107 行）在光标位于 codeBlock 内、或 codeBlock 数量变化、或某 step 完全覆盖某 codeBlock 时，会对**整个文档所有 codeBlock** 同步重跑 `lowlight.highlight()`（hljs 词法分析，CPU 密集）。文档里有 N 个代码块时粘贴一次重算 N 个，主线程冻结几十~几百 ms。
- `src/lib/extensions/lowlight.ts` 已有的 `highlightAuto → plaintext` 兜底只覆盖无语言代码块，对指定语言的代码块粘贴无效。
- 修复（方案 B）：在 `src/lib/extensions/codeBlockExtension.tsx` 重写 `addProseMirrorPlugins`，**不 spread 官方 parent 插件**，改用自写的 `createIncrementalLowlightPlugin`：
  - `apply` 先 `decoSet.map(transaction.mapping, newState.doc)` 平移装饰（廉价）
  - 再用 `transaction.changedRange()` 取变更区间（新文档坐标系），`nodesBetween` 只在区间内找受影响的 codeBlock
  - 仅对受影响块 `remove` 旧装饰 + `highlightBlockDecorations` 重算 + `add` 新装饰
  - 其余 codeBlock 装饰原样保留，不再重跑 hljs
- 注意点：
  - API 是 `transaction.changedRange()`（单数，返回 `{from,to} | null`），不是 `changedRanges()`
  - CodeBlockLowlight 的 parent `addProseMirrorPlugins` 只返回官方 LowlightPlugin，跳过它不影响基类 CodeBlock（其用 inputRules/keyboardShortcuts）
  - `lowlightPluginKey` 用共享 `PluginKey<DecorationSet>('lowlight')` 让 `decorations` prop 取状态
- 验证：`tsc --noEmit` + `npm run build` 全通过，零类型错误。

## 修复点击标题与一级标题之间空白跳到文档末尾的 bug

- 文件：`src/components/editor/BlockEditor.tsx`
- 现象：点击文档标题 `<input>` 与编辑器首个一级标题之间的空白区域，光标会直接跳到文档末尾。
- 根因：`handleBlankAreaClick` 注释本意是"点击编辑器内容下方的空白 → focus end"，但实现只检查 `target.closest('.ProseMirror')` 为空且 `target.tagName !== 'INPUT'`。标题 input 外层是带 `pb-4` padding 的容器 div，标题容器与 `.tiptap-editor-container` 之间也有间隙，这些空白区域的 target 既不是 ProseMirror 也不是 INPUT，于是误触发 `focus('end')`。
- 修复：在执行跳转前增加 Y 坐标判定 —— 取 `editor.view.dom.getBoundingClientRect()` 的 top，仅当点击 Y 坐标 `>= pmRect.top`（即点击位于编辑器内容区域或其下方）才允许跳到末尾；点击位于编辑器上方的标题区域不触发。这样只有真正落在编辑器内容下方的空白才会 focus('end')。
