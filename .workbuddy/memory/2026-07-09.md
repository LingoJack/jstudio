# 2026-07-09 工作日志

## 修复切换文档丢失内容 bug（严重，数据丢失）

**现象**：打开文档→切换到另一文档，原文档内容被清空（变单个空块）。用户文档多为 Markdown 导入（大文档，section 多）。07-08 之前的构建无此问题。

**根因**：07-08 提交 `9bf9076`（修 SectionOutline 为空时引入）在 `SectionedBlockEditor` load effect 里新增了"切换文档前 flush outgoing doc"逻辑，遍历 section editors 调 `ed.getJSON()` 读"当前内容"。致命时序：
1. `activeDocId` 变化 → React 重渲染，`key=${activeDocId}:${s.id}` 全变 → 旧 SectionEditor 卸载、新的用**旧 sections 的 blocks** 挂载
2. 新 editor 创建时内容是初始空 paragraph，真正 `setContent` 被安排在 `setTimeout(0)`（macrotask）
3. SectionedBlockEditor 的 load effect（passive effect）在新 editor 的 `setContent`（macrotask）**之前**执行
4. `ed.getJSON()` 返回空 `{type:'paragraph'}`，`tiptapJSONToOurBlocks` 转成单个空文本块
5. `flushBlocksToDoc(outgoingDocId, [空块])` 把 outgoing doc 完整内容覆盖成"一个空块" → 数据丢失

**为何 `s.blocks` 才是对的源**：SectionEditor 的 unmount cleanup（commit 阶段同步，早于 passive effect）已把 pending（未 debounce）编辑经 `handleSectionChange` 同步到 `sectionsRef.current[idx].blocks`。无 pending 编辑时 s.blocks 是初始值（=store activeDoc.blocks，完整）。所有场景 s.blocks 都持有 outgoing doc 的正确内容。读 `editor.getJSON()` 不仅多余且有害（读到 setContent 前的空状态）。

**修复**（`SectionedBlockEditor.tsx`）：flush 改为 `current.flatMap((s) => s.blocks)`，不再读 `ed.getJSON()`；移除不再使用的 `tiptapJSONToOurBlocks` import。`npx tsc --noEmit` 通过。

**教训**：React effect 时序里，passive effect（父）早于 `setTimeout(0)`（子组件 deferred setContent）。在 passive effect 里读子组件 editor 的状态，可能读到 setContent 前的初始空状态。跨组件读 imperative state 要确认时序，优先用已被 cleanup 同步过的 ref/state。

## IME 切换英文时拼音去空格（终端 + 编辑器）

需求：中文输入法输入拼音过程中切换到英文输入法，当前候选框里的原始拼音串（如 "ni hao"，带分词空格）会被 IME 整体提交到光标。期望去掉空格（"nihao"）再插入。

实现：
- 新建共享 util `src/lib/ime/pinyinStrip.ts`：`isRawPinyinCommit(data)`（含空格 + 全 ASCII 字母/空格 + 含字母）+ `stripPinyinSpaces(data)`。正常选词提交是中文无空格，不受影响。
- **终端侧** `useTerminalManager.ts`：xterm compositionend 后用 `setTimeout(0)` 读 textarea.value → onData，所以 preventDefault 对 compositionend 无效。改在 `bridgeCompositionEnd` 记录 `lastCompositionEndData`，`term.onData` 里精确匹配（`data === lastCompositionEndData` + 120ms 时间窗口 + 拼音特征）后用去空格版本 `ptyWrite`。消费一次即清空，避免误伤粘贴。
- **编辑器侧** `imeCapsLockFix.ts`：扩展原 CapsLock 幻影字符插件，新增独立于 CapsLock 的拼音去空格逻辑。compositionend 检测拼音带空格 → beforeinput(insertText) 里 `view.dispatch(tr.insertText(cleaned))` + preventDefault。handleTextInput 加对称 fallback。BlockEditor + sectionEditor 都注册了该扩展，改一处全覆盖。
- `npx tsc --noEmit` 通过，零错误。

## Link Preview Tabs 重写（浏览器式多 webview 窗口）

`src-tauri/src/commands/link_tabs.rs` + `src/components/windows/LinkPreviewTabsApp.tsx` 全面重写，修复"打不开 + tab 位置不对"的 bug，改为仿浏览器布局。

### 后端 (link_tabs.rs) 修复的核心 bug：
1. **DPI 缩放错误**（最关键）：`window.inner_size()` 返回 PhysicalSize，原代码直接 `as f64` 当 LogicalSize 用 → Retina 屏 webview 宽高 2×。新增 `logical_window_size()` 用 `physical.to_logical(scale_factor)` 正确转换。
2. **UI webview label 冲突**：原固定 `"ui-tabs"`，多窗口时第二个窗口 `add_child` 失败。改为 `format!("ui-{}", window_label)` 每窗口唯一。
3. **Tab ID 碰撞**：原 `tab-{毫秒时间戳}`，同毫秒多次 window.open 会覆盖。改用 `AtomicU64` 全局递增计数器。
4. **无 resize 处理**：窗口缩放后 content webview 不跟随。新增 `window.on_window_event` 监听 `Resized`/`ScaleFactorChanged` → `layout_webviews()` 重排 UI + active content。`Destroyed` 时清理 manager 注册表。
5. **状态不同步**：前端监听 `link-preview:tabs-updated` 但 Rust 从未 emit。现在每次 add/close/switch/navigate/title/loading 变化都 `emit_tabs_updated()` 推全量 `TabsState`。
6. **关闭的 tab webview 不销毁**：原只移到 Y=9999，内存泄漏。改用 `webview.close()` 真正销毁。
7. **navigate 不更新 tab.url**：refresh 会刷旧 URL。新增乐观更新 + `on_page_load` 回调确认最终 URL。
8. **无标题/加载跟踪**：新增 `on_document_title_changed`（更新标题）+ `on_page_load`（Started→loading=true, Finished→loading=false + 更新 URL）。

### 前端 (LinkPreviewTabsApp.tsx) 重写：
- **布局改为浏览器式**：tab strip 在顶部（edge-to-edge，非浮动 glassmorphism capsule），address bar 在下方。弃用共享 TabBar 组件，自建 `.link-preview-tab` 系列 CSS class。
- **统一事件同步**：只监听 `link-preview:tabs-updated` 一个事件，全量替换 state（删除原来监听 `tab-added` + 前端本地推断的易错逻辑）。
- **URL 智能规范化**：含点无空格→加 `https://`；否则→Google 搜索。
- **about:blank 处理**：tab 标题显示 "New Tab"，地址栏显示空。
- **CSS**：tab strip + address bar 加 `-webkit-app-region: drag`（空白区可拖窗口），交互元素 `no-drag`。

### 关键 API（Tauri 2.11.2）：
- `WebviewBuilder::on_document_title_changed(Fn(Webview, String))` — 页面 title 变化
- `WebviewBuilder::on_page_load(Fn(Webview, PageLoadPayload))` — `PageLoadEvent::Started/Finished`
- `WebviewBuilder::on_navigation(Fn(&Url)->bool)` — 导航前拦截（本次未用）

### 修复地址栏输入无响应

- **教训**：`-webkit-app-region: drag` 在有原生标题栏的窗口上是多余且有害的，会拦截子元素点击

## CollapsibleView 标题输入修复（系统排查）

`src/components/editor/nodes/CollapsibleView.tsx` — 折叠块标题 input 无法输入。

### 真正根因：WKWebView 的 contentEditable={false}

深入查 ProseMirror + TipTap 源码后发现：
- TipTap `NodeView.stopEvent` **默认已对 INPUT 返回 true** → ProseMirror 不应拦截 input 事件
- ProseMirror 的 `beforeinput` handler 对普通文本不调 `preventDefault()`
- `imeCapsLockFix` 的 handlers 大部分返回 false

**真正根因是 WKWebView 浏览器级行为**：`contentEditable={false}` 在 `contentEditable={true}` 内创建"非编辑岛"，WebKit 阻止岛内 form control 的键盘输入——input 能聚焦但无法输入字符。JavaScript 事件 shield 无法绕过。

### 修复

**移除 header div 上的 `contentEditable={false}`**。没有它：
- WKWebView 不再把 header 当非编辑岛 → input 键盘输入正常
- TipTap `stopEvent` 仍对 INPUT 返回 true（在 contentDOM 之外）→ ProseMirror 仍忽略 input 事件
- 点击 header 背景：`stopEvent` 返回 false → ProseMirror 处理 → NodeSelection + preventDefault 阻止 text caret
- 点击 input：`stopEvent` 返回 true → ProseMirror 忽略 → input 正常聚焦

同时添加完整事件 shield（mousedown + keydown 全部 + beforeinput + composition）作为 defense-in-depth。

### 教训
- **WKWebView `contentEditable={false}` 阻止内部 form control 键盘输入**——浏览器级行为，非 ProseMirror 问题
- NodeView 内 form control：**不要**在祖先加 `contentEditable={false}`，让 TipTap `stopEvent` 处理隔离
