## 修复切换文档丢失内容 bug（严重，数据丢失）

**现象**：打开文档→切换到另一文档，原文档内容被清空（变单个空块）。用户文档多为 Markdown 导入（大文档，section 多）。07-08 之前的构建无此问题。

**根因**：07-08 提交 `9bf9076`（修 SectionOutline 为空时引入）在 `SectionedBlockEditor` load effect 里新增了"切换文档前 flush outgoing doc"逻辑，遍历 section editors 调 `ed.getJSON()` 读"当前内容"。致命时序：
1. `activeDocId` 变化 → React 重渲染，`key=${activeDocId}:${s.id}` 全变 → 旧 SectionEditor 卸载、新的用**旧 sections 的 blocks** 挂载
2. 新 editor 创建时内容是初始空 paragraph，真正 `setContent` 被安排在 `setTimeout(0)`（macrotask）
3. SectionedBlockEditor 的 load effect（passive effect）在新 editor 的 `setContent`（macrotask）**之前**执行
4. `ed.getJSON()` 返回空 `{type:'paragraph'}`，`tiptapJSONToOurBlocks` 转成单个空文本块
5. `flushBlocksToDoc(outgoingDocId, [空块])` 把 outgoing doc 完整内容覆盖成"一个空块" → 数据丢失

**为何 `s.blocks` 才是对的源**：SectionEditor 的 unmount cleanup（commit 阶段同步，早于 passive effect）已把 pending（未 debounce）编辑经 `handleSectionChange` 同步到 `sectionsRef.current[idx].blocks`。无 pending 编辑时 s.blocks 是初始值（=store activeDoc.blocks，完整）。所有场景 s.blocks 都持有 outgoing doc 的正确内容。读 `editor.getJSON()` 不仅多余且有害（读到 setContent 前的空状态）。

**修复**（`SectionedBlockEditor.tsx`）：flush 改为 `current.flatMap((s) => s.blocks)`，不再读 `ed.getJSON()`；移除不再使用的 `tiptapJSONToOurBlocks` import。`npx tsc --noEmit` 通过。

**教训**：React effect 时序里，passive effect（父）早于 `setTimeout(0)`（子组件 deferred setContent）。在 passive effect 里读子组件 editor 的状态，可能读到 setContent 前的初始空状态。跨组件读 imperative state 要确认时序，优先用已被 cleanup 同步过的 ref/state。

## CollapsibleView 标题输入修复（系统排查）

`src/components/editor/nodes/CollapsibleView.tsx` — 折叠块标题 input 无法输入。

### 真正根因：WKWebView 的 contentEditable={false}

深入查 ProseMirror + TipTap 源码后发现：
- TipTap `NodeView.stopEvent` **默认已对 INPUT 返回 true** → ProseMirror 不应拦截 input 事件
- ProseMirror 的 `beforeinput` handler 对普通文本不调 `preventDefault()`
- `imeCapsLockFix` 的 handlers 大部分返回 false

**真正根因是 WKWebView 浏览器级行为**：`contentEditable={false}` 在 `contentEditable={true}` 内创建"非编辑岛"，WebKit 阻止岛内 form control 的键盘输入——input 能聚焦但无法输入字符。JavaScript 事件 shield 无法绕过。

### 修复

**移除 header div 上的 `contentEditable={false}`**。没有它：
- WKWebView 不再把 header 当非编辑岛 → input 键盘输入正常
- TipTap `stopEvent` 仍对 INPUT 返回 true（在 contentDOM 之外）→ ProseMirror 仍忽略 input 事件
- 点击 header 背景：`stopEvent` 返回 false → ProseMirror 处理 → NodeSelection + preventDefault 阻止 text caret
- 点击 input：`stopEvent` 返回 true → ProseMirror 忽略 → input 正常聚焦

同时添加完整事件 shield（mousedown + keydown 全部 + beforeinput + composition）作为 defense-in-depth。

### 教训
- **WKWebView `contentEditable={false}` 阻止内部 form control 键盘输入**——浏览器级行为，非 ProseMirror 问题
- NodeView 内 form control：**不要**在祖先加 `contentEditable={false}`，让 TipTap `stopEvent` 处理隔离
