## 修复 SectionOutline 大纲为空 bug

**现象**：部分文档 DB 中有正确的 heading blocks（heading-2/heading-3 + RichText[] 内容），但右侧 SectionOutline 面板显示"无大纲"。某些文档正常，某些为空。DB 数据完整（已用 sqlite3 + Python 验证全部 1041 个 heading block 均有非空 RichText[] content）。

**根因**：纯前端 reactivity/sync 问题，非数据问题。两个层面：
1. **文档切换时 outgoing doc 的 pending edits 丢失**：SectionedBlockEditor 切换文档时，SectionEditor 的 unmount cleanup 调 `handleSectionChange` → `setActiveDocBlocks`，但 ownership guard（`docId !== activeDoc.id → return`）丢弃了编辑（因为 activeDoc 已指向新文档）。导致 `documents[]` 里 outgoing doc 的 blocks 是旧快照，切回去时 outline 读到过期数据。
2. **SectionOutline 只从 store 单源提取 headings**：当 `activeDoc.blocks` 因上述原因过期/为空时，没有 fallback 数据源。而 section editors 的 ProseMirror doc 里其实有正确的 heading 节点（setContent 加载的内容），只是 `setContent({ emitUpdate: false })` 不会同步回 store。

**修复**（2 个文件）：

### SectionOutline.tsx
- 改为双源合并提取 headings：
  - 源1：`activeDoc.blocks`（store，覆盖未挂载的 section）
  - 源2：mounted section editors 的 ProseMirror doc（`editor.state.doc.descendants()` 遍历 heading 节点，还能抓到 collapsible 内嵌的 heading）
  - 按 id 去重合并，store 优先
- 订阅 `activeDocId` 触发重新提取（防御 blocks ref 复用）
- 订阅 editor 的 `transaction`/`update` 事件触发重新提取（catch setContent 加载的内容）
- 渐进挂载（progressive mounting）时用 4 个 timer（100/300/800/2000ms）重新订阅新挂载的 editor

### SectionedBlockEditor.tsx
- 文档切换前 flush outgoing doc 的 pending edits：遍历所有 mounted section editor，`ed.getJSON()` → `tiptapJSONToOurBlocks()` 序列化当前内容（含未 debounce 的编辑），调 `flushBlocksToDoc(outgoingDocId, full)` 写入 `documents[]`
- 新增 `import { tiptapJSONToOurBlocks } from tiptapAdapter`

**验证**：`npx tsc --noEmit` 通过，`npm run build` 通过。

## CollapsibleView 标题无法输入文字 bug 修复

**文件**: `src/components/editor/nodes/CollapsibleView.tsx`

**根因（两层）**:
1. ProseMirror 在 `view.dom` 上的 `beforeinput` 处理器不检查 target 是否表单控件，
   对所有冒泡上来的 beforeinput 调用 `preventDefault()`，取消浏览器对 `<input>` 的
   原生字符插入。
2. 即使 shield 了 beforeinput，`input` 事件仍冒泡到 ProseMirror 的
   `editHandlers.input`，其调用 `domObserver.flush()` 可能触发 NodeView 重新渲染，
   导致受控组件 `value` 被重置回旧值——字符"闪现后消失"。

**最终修复（三管齐下）**:
1. **非受控 input**：`defaultValue` + `ref` 替代 `value` + `onChange`，浏览器直接管理
   值，不依赖 React state，扛住任何 ProseMirror 触发的重渲染。移除了 `useState`。
2. **shield 全部相关事件**（wrapper 上原生 bubble-phase stopPropagation）：`mousedown`
   / `keydown`(导航键) / `beforeinput` / `input` / `compositionstart|update|end`。
3. **原生 `input` 监听器**挂在 `<input>` 元素本身（target 阶段，先于 wrapper 的
   stopPropagation），通知 cursor trail `markDirty()`。

外部同步：`useEffect([summary])` 在 input 未聚焦时手动 `el.value = summary`。
提交：`commitSummary` 从 `inputRef.current.value` 直接读取。

**教训**：在 ProseMirror NodeView 内放原生 `<input>` 时，受控组件不可靠——必须用
非受控 + 全量事件 shield。此模式可复用于其他含表单控件的 NodeView。

**⚠️ 已回退**：用户反馈修复无效且过度 hack，已通过 `git checkout 33c20cc -- <file>`
回退上述全部代码更改。CollapsibleView.tsx 恢复为原始受控组件版本。标题无法输入
的 bug 仍未解决，需要换思路（可能需要从 NodeView 架构层面重新考虑，而非事件 shield）。

## 修复 dark 主题表格工具栏"白色框"遗留 bug

**现象**：dark 主题下 TableControls（行/列/对齐工具栏）边框显示为白色框，light 主题不明显。pre-existing bug，非本次主题统一引起。

**根因**：Tailwind v4 无法编译带嵌套 `var()` fallback 的 arbitrary value 类。`border-[var(--vscode-menu-border, var(--vscode-widget-border))]` 不生成任何 CSS 规则，`border-color` 回退到浏览器默认 `currentColor`（=文字色）。dark 下文字 #CCCCCC 近白 → 白色框；light 下文字 #3B3B3B 深灰 → 与预期边框色接近，不明显。

**验证方法**：提取 dist CSS，发现只有 `.border-[var(--vscode-menu-border)]`（无 fallback）被编译，带嵌套 fallback 的版本不存在。

**修复**：去掉 Tailwind 类里的嵌套 fallback，直接用 `var(--vscode-menu-border)`（该变量在所有4主题 + :root + .dark 都有定义，无需 fallback）。涉及 TableControls.tsx（4处：工具栏外框、分隔线、下拉面板、分隔符）+ MenuList.tsx（1处）。CSS 原生规则里的 `var()` fallback 保留（不受 Tailwind 限制）。

**教训**：Tailwind v4 arbitrary value 里不要用嵌套 `var(a, var(b))` fallback。排查命令：`grep -rn '\[var(--vscode-[a-z-]*,\s*var(--vscode-'`

## 修复 LinkView 编辑后点击仍跳旧 URL bug

**文件**: `src/components/editor/nodes/LinkView.tsx`（`handleSaveEdit`）

**现象**：链接块编辑 URL（A→B）保存后，点击/双击卡片或工具栏「打开预览/浏览器」仍跳到旧地址 A。fetch 慢或卡住时稳定复现。

**根因（时序问题）**：`handleSaveEdit` 里 `setEditing(false)` 同步执行，组件立即切回 loaded-card 状态；但 `updateAttributes({ url: B })` 写在 `storage.fetchLinkMetadata(B).then(...)` 异步回调里，要等 fetch 完成（几百 ms~数秒）才执行。在 fetch 完成前 `node.attrs.url` 仍是旧值 A，卡片显示旧信息，此时任何点击/双击/工具栏「打开」动作（`handleOpenPreview`/`handleOpenExternal`/双击 `onDoubleClick`，均依赖 `url` prop）都会导航到旧 URL A。

**已排除**：① Rust 端 `open_link_preview_with_tabs` 每次用 timestamp 生成新窗口 label，非单例复用旧 URL；② storage.ts 层仅透传 invoke 无缓存；③ 无全局 plugin 拦截 linkBlock 点击（grep 确认所有打开路径都在 LinkView 内部）。placeholder 场景的 `submitUrl` 虽也是异步 updateAttributes，但 fetch 期间 `url` 仍为空 → 卡片停在 placeholder 态无东西可点，故不受影响。

**修复（乐观更新）**：URL 改变时立即**同步** `updateAttributes({ url: normalized, title: newTitle || hostname, description/favicon/ogImage/siteName: '' })`，让组件立即用新 URL 渲染（点击打开新地址）；再异步 fetch 补全 metadata，成功后第二次 `updateAttributes` 用 `meta.url`（可能为重定向最终 URL）+ 完整字段覆盖。fetch 失败时保留乐观值（catch 内不再重复写）。URL 未变的分支只更新 title。

**验证**：`npx tsc --noEmit` 通过。

## 修复 inline link（行内蓝色链接）编辑文字后 autolink 不更新 href 的 bug

**文件**: 新增 `src/lib/editor/extensions/customLinkAutolink.ts`；改 `sectionEditor/extensions.ts` + `BlockEditor.tsx` 的 Link 配置。

**澄清过程**：用户最初 @ LinkView.tsx 报"链接编辑后点击跳旧地址"，但实际说的是**行内 inline link mark**（`@tiptap/extension-link` 的蓝色文字，点击跳转），不是 linkBlock 卡片。第一轮误修了 LinkView.handleSaveEdit 的时序（也是真实 bug，保留乐观更新）。

**根因**：`@tiptap/extension-link` 的 autolink plugin（node_modules/.../helpers/autolink.ts:158-165）对**已有 link mark** 的文字直接跳过、不更新 href：
```ts
.forEach(link => {
  if (getMarksBetween(link.from, link.to, doc).some(i => i.mark.type === type)) return; // 跳过！
  tr.addMark(link.from, link.to, type.create({ href: link.href }));
})
```
用户在 link 文字上"删除/打字"改 URL 后，残留旧 link mark（href=旧），autolink 重新扫描检测到新 URL，但 `getMarksBetween` 发现已 link mark → return，href 永不更新。点击 `<a href=旧>` → 跳旧地址。

**点击跳转机制（关键认知）**：editable 模式 `openOnClick: false`，clickHandler.handleClick 进入但 openOnClick false 不 `window.open`，返回 false（不 preventDefault）→ 浏览器原生 `<a target="_blank">` 默认行为触发 → Tauri `on_new_window` 拦截 → 预览窗口。所以 editable 下点击 inline link **能跳**（靠 `<a>` 默认行为没被阻止），href 来自 link mark 的 attrs。

**修复**：新建 `customLinkAutolink.ts`（复制上游 autolink 逻辑，改 forEach：已有 link mark 且 `href !== 检测值` 时 `removeMark` + `addMark` 更新 href）。两处 Link 配置改为 `autolink: false` + `addProseMirrorPlugins` 注册自定义 plugin：
```ts
Link.extend({
  addProseMirrorPlugins() {
    return [customLinkAutolink({ type: this.type, defaultProtocol: 'https' })];
  },
}).configure({ openOnClick: ..., autolink: false })
```
`markdownImport.ts` 的 headless 解析器不改（初始导入 markdown 不涉及编辑场景）。

**验证**：`npx tsc --noEmit` 通过。

**功能缺口（未做）**：项目目前**没有** inline link href 的编辑 UI（`setLink`/`toggleLink` 命令存在但无任何 UI 调用，FormatBubbleMenu 只有 bold/italic/strike/code，命令面板/快捷键无 link）。用户只能通过改文字为 URL 让 autolink 更新 href，无法像 Notion 那样改显示文字+独立 href。后续可考虑加 link 编辑气泡。
