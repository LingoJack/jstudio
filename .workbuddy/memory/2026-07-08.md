## CollapsibleView 标题无法输入文字 bug 修复

**文件**: `src/components/editor/nodes/CollapsibleView.tsx`

**根因（两层）**:
1. ProseMirror 在 `view.dom` 上的 `beforeinput` 处理器不检查 target 是否表单控件，
   对所有冒泡上来的 beforeinput 调用 `preventDefault()`，取消浏览器对 `<input>` 的
   原生字符插入。
2. 即使 shield 了 beforeinput，`input` 事件仍冒泡到 ProseMirror 的
   `editHandlers.input`，其调用 `domObserver.flush()` 可能触发 NodeView 重新渲染，
   导致受控组件 `value` 被重置回旧值——字符"闪现后消失"。

**最终修复（三管齐下）**:
1. **非受控 input**：`defaultValue` + `ref` 替代 `value` + `onChange`，浏览器直接管理
   值，不依赖 React state，扛住任何 ProseMirror 触发的重渲染。移除了 `useState`。
2. **shield 全部相关事件**（wrapper 上原生 bubble-phase stopPropagation）：`mousedown`
   / `keydown`(导航键) / `beforeinput` / `input` / `compositionstart|update|end`。
3. **原生 `input` 监听器**挂在 `<input>` 元素本身（target 阶段，先于 wrapper 的
   stopPropagation），通知 cursor trail `markDirty()`。

外部同步：`useEffect([summary])` 在 input 未聚焦时手动 `el.value = summary`。
提交：`commitSummary` 从 `inputRef.current.value` 直接读取。

**教训**：在 ProseMirror NodeView 内放原生 `<input>` 时，受控组件不可靠——必须用
非受控 + 全量事件 shield。此模式可复用于其他含表单控件的 NodeView。

**⚠️ 已回退**：用户反馈修复无效且过度 hack，已通过 `git checkout 33c20cc -- <file>`
回退上述全部代码更改。CollapsibleView.tsx 恢复为原始受控组件版本。标题无法输入
的 bug 仍未解决，需要换思路（可能需要从 NodeView 架构层面重新考虑，而非事件 shield）。

## 修复 dark 主题表格工具栏"白色框"遗留 bug

**现象**：dark 主题下 TableControls（行/列/对齐工具栏）边框显示为白色框，light 主题不明显。pre-existing bug，非本次主题统一引起。

**根因**：Tailwind v4 无法编译带嵌套 `var()` fallback 的 arbitrary value 类。`border-[var(--vscode-menu-border, var(--vscode-widget-border))]` 不生成任何 CSS 规则，`border-color` 回退到浏览器默认 `currentColor`（=文字色）。dark 下文字 #CCCCCC 近白 → 白色框；light 下文字 #3B3B3B 深灰 → 与预期边框色接近，不明显。

**验证方法**：提取 dist CSS，发现只有 `.border-[var(--vscode-menu-border)]`（无 fallback）被编译，带嵌套 fallback 的版本不存在。

**修复**：去掉 Tailwind 类里的嵌套 fallback，直接用 `var(--vscode-menu-border)`（该变量在所有4主题 + :root + .dark 都有定义，无需 fallback）。涉及 TableControls.tsx（4处：工具栏外框、分隔线、下拉面板、分隔符）+ MenuList.tsx（1处）。CSS 原生规则里的 `var()` fallback 保留（不受 Tailwind 限制）。

**教训**：Tailwind v4 arbitrary value 里不要用嵌套 `var(a, var(b))` fallback。排查命令：`grep -rn '\[var(--vscode-[a-z-]*,\s*var(--vscode-'`
