## 修复终端光标「双下划线」问题

现象：终端光标出现两条一样的下划线。

根因：终端同时叠了两套光标——(1) xterm.js 原生光标（useTerminalManager 里 cursorStyle:'underline' + cursorBlink），(2) 自定义 WebGL `CursorTrail`（仿 kitty cursor trail）。CursorTrail 原本用 cutout（镂空）模式想透出原生光标，但拖尾彗尾也是下划线形状，移动时与原生光标错位形成双下划线。

方案（用户选「拖尾即光标」，对齐编辑器实现）：
- `src/components/terminal/CursorTrail.ts`：重写 `getRenderOptions()` 返回 `{ fillCursor:true, blink }`（FILL 模式，拖尾本身作为唯一光标）；移除会冻结 blink 的 `isIdle()` override，改用基类默认 + `shouldThrottle()`/`throttleFps()=20` 降帧维持平滑闪烁；新增 `cursorVisibleStartTime` 计时 + `computeBlink()`（sine 渐变，与 EditorCursorTrail 的 BLINK_SOLID_MS=530/BLINK_PERIOD_MS=1060 一致），在 updateTarget 检测光标移动时重置计时使移动后立即实心。
- `src/components/terminal/PaneLayoutView.tsx`：trail 可用时把 xterm `cursorHidden=true`（Effect1 挂载循环 + Effect2 attach 的两条路径都改为 `cursorHidden = !!trail`）；无 WebGL2 时回退保留原生光标。

注：终端拖尾两个类同源——`cursor/BaseCursorTrail`（GL/物理/渲染基类，FILL/CUTOUT 由 shader u_fillCursor 控制）、`cursor/EditorCursorTrail`（编辑器版，本来就是 FILL）。撕离子窗口 TerminalWindowApp 复用同一 PaneLayoutView，改动自动生效。tsc -p tsconfig.app.json 通过。

## 调研：自研画板替换 Excalidraw（draw.io 风格，画时序图/用例图）

需求：用户想自研结构化画板替换现成的 Excalidraw，参考 draw.io，核心场景=时序图/用例图。

集成边界（关键，迁移面很干净）：
- 编辑器层（不变）：`diagramExtension.ts`（TipTap atom 节点，属性核心只有 `snapshot: string` + width/height/align）→ `DiagramBlockView.tsx`（选中/2D缩放/工具栏/放大新窗口）→ `DiagramWindowApp.tsx`（独立 OS 窗口全屏编辑）。
- 画板层（可替换）：`ExcalidrawCanvas.tsx` 是唯一耦合 Excalidraw 的文件，对外仅 `initialSnapshot`(进) / `onChange(json)`(出) + darkMode/editing。
- 跨窗口：`lib/windows/diagramWindow.ts` 通过 Rust 内存命令 set/get_preview_data + 轮询 get_diagram_update 回传 snapshot，blockId 防串。snapshot 是不透明字符串，换内核只需保证自洽。

引擎选型结论：
- draw.io 底层是 mxGraph，但 mxGraph 2020 已 EOL/归档。官方现代继任者 = **maxGraph (`@maxgraph/core`)**，TS 重写、tree-shakable、活跃维护（0.23.0 @ 2026-03）。自带正交/Manhattan/肘形连线路由、端口绑定、undo/redo、层次/树布局——即"draw.io 同款底层"今天的正确落地。
- 用户已拍板：① 底层用图引擎（draw.io 同款思路，即 maxGraph）+ 上层全自研；② 第一阶段先做通用流程图（矩形/菱形/连线）打底，时序图/用例图作为其上的模板。

自研内核分层：①GraphModel(可序列化→snapshot) ②SVG渲染 ③交互(选中/拖拽/端口拖连线/正交路由) ④模具库(矩形/椭圆/菱形/actor/生命线/激活条) ⑤图模板(时序图/用例图) ⑥文本编辑+undo/redo+复制粘贴。

替换策略：新增 `GraphCanvas.tsx`（与 ExcalidrawCanvas 同接口 initialSnapshot/onChange/darkMode/editing），DiagramBlockView/DiagramWindowApp 改导入即可切换，可灰度共存。snapshot 内核格式自定义（nodes[]/edges[]），需与 Excalidraw 旧格式做识别兼容（旧文档迁移或并存）。

## 实现：自研画板内核 GraphCanvas（阶段0+1 落地）

已安装 `@maxgraph/core@0.23.0`。新增目录 `src/components/editor/nodes/graph/`：
- `graphSnapshot.ts`：自研快照格式（`{kind:'jgraph',version,nodes[],edges[],viewport}`）+ `detectSnapshotKind()` 三态识别（empty/jgraph/excalidraw/unknown，以 `kind` magic key 与 elements 数组特征区分新旧）+ parse/serialize。
- `graphModel.ts`：snapshot ↔ maxGraph 双向转换。形状映射：rounded→rectangle+rounded:true、diamond→rhombus、ellipse、text→shape:text 无填充描边。连线默认 orthogonalEdgeStyle+classic 箭头。applySnapshotToGraph(清空重建,id 复用 Cell id 可逆) / readSnapshotFromGraph(读回含视口)。
- `GraphCanvas.tsx`：与 ExcalidrawCanvas 完全同签名的组件。maxGraph 初始化用 `new Graph(container, undefined, [...getDefaultPlugins(), RubberBandHandler])`；setPanning/setConnectable/setCellsEditable/setAllowDanglingEdges(false)；UndoManager 监听 InternalEvent.UNDO（model+view）；model CHANGE→防抖400ms序列化回传（applyingRef 防程序化灌入回环）；editing=false→setEnabled(false)+setCellsLocked(true) 只读；左侧竖排工具栏插入矩形/圆角/椭圆/菱形/文本+撤销/重做/删除；Del/⌘Z/⌘⇧Z 键盘。

接入：DiagramBlockView 与 DiagramWindowApp 都按 detectSnapshotKind 路由——旧 excalidraw 快照继续用 ExcalidrawCanvas（向后兼容），空白/jgraph 用 GraphCanvas。DiagramBlockView 用 useRef 锁定判定（仅挂载时一次，防编辑中格式从 empty→jgraph 反复切内核丢状态）。样式加在 vscode-theme.css（.jgraph-* ，含暗色）。

验证：tsc -p tsconfig.app.json 通过；vite build 成功，maxGraph 正常打包。maxGraph 0.23 关键 API 已核实存在：getStylesheet().getDefaultEdgeStyle()、getChildVertices/getChildEdges、scaleAndTranslate、getTerminal、setCellsLocked。浏览器实测（建临时 graphtest.html+__graphtest__/main.tsx 独立挂载 GraphCanvas，agent-browser 加载）：画布渲染正常、点工具栏插入矩形/椭圆 snapshot 正确序列化为 jgraph 格式、撤销回退节点生效、节点选中显示端口手柄。测试文件已删。

注：agent-browser Chromium 版本坑——install 下了 1228 但 daemon 要 1208，软链 chromium_headless_shell-1228 → 1208 路径即可（同系列兼容）。

## 优化：GraphCanvas 编辑体验对齐 draw.io（第一+第二档）

用户诉求：图形大小/逻辑/操作体验对齐 draw.io。用户拍板：做第一+第二档，尺寸配色完全对齐 draw.io。全部改在 `GraphCanvas.tsx` + `vscode-theme.css`，均为开引擎能力（非裸写）。

maxGraph 0.23 API 落地（均已核实并实测）：
- 网格+吸附：`graph.setGridEnabled(true)` + `setGridSize(10)`（拖拽自动吸附）。方法在 mixin/SnapMixin。
- 缩放：`zoomIn/zoomOut/zoomActual/zoom(factor,center)`（mixin/ZoomMixin）；`graph.centerZoom=true` 以视口中心为锚。Ctrl/Cmd+滚轮缩放（container wheel listener，passive:false + preventDefault，ZOOM_MIN 0.25/MAX 4）。
- 自适应：`graph.getPlugin<FitPlugin>('fit')?.fitCenter({margin:24})`（FitPlugin 已在 getDefaultPlugins）。双击空白→fitCenter：监听 `InternalEvent.DOUBLE_CLICK`，evt.getProperty('cell') 为空即空白（比 DOM querySelector 判定稳）。
- 参考线：`graph.getPlugin<SelectionHandler>('SelectionHandler').guidesEnabled=true`（拖动显示对齐辅助线）。
- 连接点：override `graph.getAllConnectionConstraints=(terminal)=>terminal?.cell?.isVertex()? CONNECTION_POINTS.map(([x,y])=>new ConnectionConstraint(new Point(x,y),true)):null`。8 点（四边中点+四角）。悬停节点边缘 ConnectionHandler 自动高亮（实测悬停出现绿色高亮边框）。
- 复制粘贴：`Clipboard.copy/cut/paste(graph)`（util/Clipboard 静态方法，跨实例可用）。⌘D 克隆：`graph.cloneCells(cells)` + `graph.importCells(clones, GRID_SIZE, GRID_SIZE, defaultParent)` + setSelectionCells。
- 方向键微移：`graph.moveCells(cells, dx, dy)`，默认步长=GRID_SIZE(10)，Shift 时=1px 精调。键盘 handler 里先 `if(graph.isEditing())return` 让内联编辑优先。

尺寸对齐 draw.io：DEFAULT_SIZE 矩形/圆角 120×60、椭圆 120×80、菱形 80×80、文本 60×30。
配色：PALETTE.light {fill:#dae8fc,stroke:#6c8ebf,font:#1f2328,edge:#4d6b99}，dark {fill:#2b3a55,stroke:#7aa2d6,font:#e6edf3,edge:#9db8e0}。初始化时写 `getDefaultVertexStyle()`/`getDefaultEdgeStyle()`（darkModeRef 读一次）。
错位落点：insertOffsetRef 每插一个 +1 格网格、%8 循环，避免堆叠；落点 round 到 GRID_SIZE；新建即 setSelectionCell。
网格背景：.jgraph-surface 用双 linear-gradient 10px 底纹（暗色用 rgba(255,255,255,.06)）。

工具栏新增：放大/缩小/适应画布（ZoomIn/ZoomOut/Maximize 图标）。

验证：tsc 通过 + vite build 成功 + 浏览器实测（临时 graphtest.html，预置2节点1连线快照）：初始渲染=draw.io 淡蓝配色+网格+正交连线；错位落点(580,330)/(590,330) 偏移10px 且网格对齐；撤销 4→3 节点；放大 SVG min-width 扩大；fitCenter 三节点全入视野；悬停节点绿色高亮（连接点生效）。临时文件已删。
