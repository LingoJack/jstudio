# 优秀 Flowchart 层级布局算法

## 当前算法的问题

### 1. BFS 分层太浅
当前用 BFS + 入度递减分层，节点被"拉"到尽可能靠上的层。但正确的做法是**最长路径分层**：每个节点放在其所有前驱的最深位置 + 1，这样节点出现在它"应该"出现的深度，图的高度最小化，语义更清晰。

### 2. 长边穿越中间层
如 A(layer 0) -> D(layer 2)，边直接跨越 layer 1，没有虚拟节点占位。这导致：
- 连线穿过 layer 1 的节点
- 交叉最小化阶段无法正确工作（因为只能优化相邻层之间的交叉）

### 3. 交叉最小化不足
当前只有一次前向 barycenter 排序。标准做法是多轮上下交替扫描（Brandes-Köpf），才能有效减少连线交叉。

### 4. 坐标分配粗糙
每层整体居中于最宽层，不考虑父子关系的对齐。父节点应该尽量居中于其子节点上方，形成视觉上的"树"感。

## 新算法设计（Sugiyama 框架简化版）

**仅修改 `flowchartConverter.ts` 的 `layoutNodes` 函数**，拆分为以下子步骤：

### Step 1: 构建有向图 + 环检测
- 构建 `outgoing` / `incoming` 邻接表
- 移除自环（A->A）
- DFS 检测环，翻转回边使其成为 DAG（贪心：翻转入度>出度的节点上的边）

### Step 2: 最长路径分层
```
layer(node) = 0                          // 如果入度为 0
layer(node) = max(layer(pred) + 1)       // 对所有前驱 pred
```
- 拓扑序遍历，保证前驱先计算
- 结果：节点数最少的分层（图高度最小）

### Step 3: 虚拟节点插入
- 对每条跨越 k>1 层的边 (u, v)：
  - 在 layer(u)+1, layer(u)+2, ..., layer(v)-1 各插入一个 dummy 节点
  - 边拆分为 (u, d1), (d1, d2), ..., (dk, v)
  - dummy 尺寸为 0，不进入最终输出
- 目的：所有边都只跨 1 层，交叉最小化才能正确工作

### Step 4: 交叉最小化（Barycenter 启发式）
- **3 轮上下交替扫描**：
  - **向下扫描**（layer 1 → 最后一层）：每层按 `barycenter = avg(上层邻居位置)` 排序
  - **向上扫描**（最后一层 → layer 1）：每层按 `barycenter = avg(下层邻居位置)` 排序
- 每次排序后立即消解同层位置冲突（保持顺序但保证间距）
- barycenter 相同时保持原序（稳定排序）

### Step 5: 坐标分配
**交叉轴（cross axis = X for TB）**：
1. 初始：每层从左到右按排序顺序放置，间距 = crossGap
2. **2 轮迭代对齐**：
   - 向下：每个节点 X = 其所有下层邻居 X 中心的平均值（如果有），否则保持
   - 向上：每个节点 X = 其所有上层邻居 X 中心的平均值
3. **消解重叠**：每层从左到右扫描，如果节点 i 右边超出节点 i+1 左边，将 i+1 及后续右移
4. 居中：整体偏移使 minX = 50

**主轴（main axis = Y for TB）**：
- 每层 Y = 上一层 Y + 上一层最大高度 + mainGap
- 从 BASE_Y=50 开始

### Step 6: 移除虚拟节点 + 输出
- 只返回真实节点的坐标
- dummy 节点被丢弃

## 不做的事
- 不实现 Brandes-Köpf 的完整 4 种对齐模式（太复杂，收益递减）
- 不实现 network simplex 层宽优化
- 不处理 subgraph（子图）嵌套
- maxGraph 的 `obstacleEdgeStyle` 负责实际连线绕障，布局只管节点位置
