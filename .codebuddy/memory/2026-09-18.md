# 2026-09-18

- diagram 画布新增 Option+滚轮缩放：`desktop/src/components/editor/nodes/graph/graphSetup/wheelZoom.ts` 缩放分支条件由 `ctrlKey || metaKey` 扩为 `ctrlKey || metaKey || altKey`。该文件是所有 GraphCanvas 共用的滚轮处理（内嵌画板 + 独立图形块），缩放为指数式、以光标为锚点，受 ZOOM_MIN/ZOOM_MAX 限制。
- 排查发现：用户日常运行 `/Applications/JStudio.app` 安装版而非 dev 模式，源码改动需 `cd desktop && make build && make install-jstudio-only`（或 `make install`）重建安装后才可见。Cmd 缩放是旧版既有行为，不能作为"新代码已加载"的证据。后续用户改为跑 dev 模式验证，不要再主动 build+install。
- mermaid 时序图消息标签抬升：`sequenceConverter.ts` 新增 `MESSAGE_LABEL_LIFT = 14`，消息边 style 带 `labelLift`（GraphEdgeStyle 新字段）；`graphModel.ts buildEdgeStyle` 把它转成 maxGraph `spacingTop = -2*labelLift`（边标签 dy=(spacingTop-spacingBottom)/2，valign=middle），文字悬在连线上方不压线；快照回写读回 `labelLift`。AI 生成时序图路径（aiGraphLayout.ts）暂未加。
- mermaid 时序图生命线间距自适应：`sequenceConverter.ts` 新增 `computeGapSpacings()`，相邻生命线间距 = max(160, 相邻消息标签实测宽 + 留白)；自环消息按回路偏移 + 标签宽 + 留白约束右侧间隙。跨多条生命线的消息不参与约束。
- 时序图垂直布局按标签高度自适应（多行标签是常态：mermaid 消息里 `<br/>` 换行）：普通消息标签抬升量 = h/2 + 4（底边恒距自己连线 4px）；行距 = max(40, 前行额外占位 + 本行 lift + h + 8)；首条消息 Y = 头部底 + lift + h + 8。自环消息：标签经 `labelShiftX`（GraphEdgeStyle 新字段 → buildEdgeStyle 转 spacingLeft = 2*shiftX）整体挪到 U 形回路竖线右侧，labelLift=0 垂直居中于回路，回路高 = max(40, h+12)。MESSAGE_LABEL_LIFT/MESSAGE_START_Y 常量已删。
- mermaid 时序图生命线长度收紧（用户明确在意的是竖向长度）：旧算法把最后一条消息之后的 MESSAGE_SPACING 和 50px 底部留白都计入高度，尾部空约 95px。改为记录 `lastMsgEndY`（自环算到回路底部），高度 = lastMsgEndY + 24；LIFELINE_DEFAULT_HEIGHT 200→150，MESSAGE_SPACING 45→40。
- 间隙宽度最终方案：字符宽度估算猜了三轮都不准（单行加总 → 0.52/0.62 细化 → 仍偏差），最终用真实测量：graphTextFit.ts 导出 `measureLabelSize()`（复用其隐藏 DOM 单例 + GRAPH_FONT_FAMILY CSS var 字体，DOM 里 var 可解析；返回 {w: 最宽行, h: 整块自然高}，`<br>` 归一为 \n，lineHeight 跟随 body 继承）；sequenceConverter.estimateLabelSize 有 DOM 时走实测，无 DOM（单测）走 0.6 字宽 × 18px 行高兜底。教训：涉及渲染尺寸的布局不要用字符数猜，直接 DOM 实测。
- mermaid 解析失败根因（`&emsp;`）：时序图词法器消息规则是 `:(?:(?:no)?wrap)?[^#\n;]*`，`;` 是语句分隔符；HTML 命名实体（`&emsp;` 等）自带 `;`，把消息拦腰截断，后半段被当新语句解析报 "Expecting ARROW got ','"。修复：`mermaidParser.parseMermaidCode` 解析前 `decodeEntities()` 预处理——空白类实体（emsp/ensp/thinsp/nbsp）还原为对应 Unicode 空格，数值实体（&#8195; / &#x2003;）解码但跳过会产生 `< > & ;` 的码点。教训：mermaid 时序图源码里消息文本含命名实体必然解析失败，用户写长参数列表时常用 &emsp; 缩进。
- 自动上色支持 database 圆柱：`graphAutoColor.ts` 不再复用 graphTextFit 的收集器（TEXT_FIT_SHAPES 决定尺寸适配规则，加 database 会误触发文字适配），改为独立 `AUTO_COLOR_SHAPES = {rectangle, rhombus, lifeline, database}` + `isAutoColorCell` + 自带遍历收集器。
