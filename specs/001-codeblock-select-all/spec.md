# Feature Specification: 代码块内 Cmd+A 全选代码

**Feature Branch**: `001-codeblock-select-all`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "我需要让代码块里可以 cmd + a 全选代码"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 光标在代码块内按 Cmd+A 只选中该代码块的内容 (Priority: P1)

用户在文档中编辑或查看一个代码块时，希望通过标准的全选快捷键
（macOS 上的 Cmd+A，Windows/Linux 上的 Ctrl+A）快速选中该代码块内的
全部代码文本，而不会连带选中代码块前后的其他文档内容（标题、段落、
其他代码块等）。

**Why this priority**: 这是用户显式提出的核心需求，是复制/替换代码
最常用的前置操作；若全选范围溢出到整篇文档，用户必须手动重新拖选，
体验受损且容易误删其他内容。

**Independent Test**: 在任意一个非空代码块内点击以放置光标，按下
Cmd+A（或 Ctrl+A），可独立验证：该代码块的全部文本被高亮选中，且
选区边界不超出该代码块。

**Acceptance Scenarios**:

1. **Given** 光标当前位于某个非空代码块的文本内（编辑状态），**When**
   用户按下 Cmd+A（macOS）或 Ctrl+A（Windows/Linux），**Then** 该代码块
   内的全部文本被选中，选区不包含该代码块之外的任何文档内容。
2. **Given** 代码块内的全部文本已通过上述快捷键被选中，**When** 用户
   执行复制（Cmd+C / Ctrl+C），**Then** 剪贴板中的内容与该代码块的
   文本完全一致（不多不少）。
3. **Given** 代码块内的全部文本已被选中，**When** 用户直接输入新字符
   或按 Delete/Backspace，**Then** 原有代码内容被替换或清空，其他
   文档内容不受影响。

---

### User Story 2 - 全选行为不影响代码块外的既有全选逻辑 (Priority: P2)

当光标不在任何代码块内时，Cmd+A 的行为应保持文档现有的"全选当前
文档内容"逻辑不变，本功能只新增/修正"光标位于代码块内"这一特定
场景下的选取范围。

**Why this priority**: 避免本次改动破坏用户已经依赖的、代码块之外的
全选习惯，属于回归风险控制，重要但非本次改动的核心目标。

**Independent Test**: 将光标放在代码块之外的正文段落中按 Cmd+A，
可独立验证：选区行为与改动前一致（选中整篇文档内容），不受本功能
影响。

**Acceptance Scenarios**:

1. **Given** 光标位于代码块之外的正文段落中，**When** 用户按下
   Cmd+A，**Then** 系统按现有行为选中整篇文档的内容，行为与本功能
   引入前一致。

---

### Edge Cases

- 代码块内容为空时按 Cmd+A：不应产生错误，也不应选中代码块之外的
  内容；视觉上无高亮或高亮区域为空即可。
- 代码块整体已作为一个"块"被选中（例如通过三击选中整块）时再按
  Cmd+A：应选中该代码块内部的代码文本（等同于光标在块内时的效果），
  而不是意外跳出到全文档选中。
- 焦点当前落在代码块的辅助控件上（例如语言选择器的搜索输入框）而非
  代码文本本身时：Cmd+A 应遵循该控件自身的默认全选行为（选中输入框
  内的文本），不应被本功能重定向到代码文本。
- 代码块正处于"渲染预览"模式（例如 HTML/Mermaid 的可视化预览覆盖了
  原始代码文本）时：由于此时没有可选中的代码文本处于可编辑/可见状态，
  本功能不适用，不应触发意外选取。
- 文档中存在多个代码块时：Cmd+A 的选取范围始终以光标当前所在的那个
  代码块为准，与其他代码块无关。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 能够判断用户的文本光标当前是否位于某个代码
  块的内容范围内。
- **FR-002**: 当光标位于代码块内容范围内时按下 Cmd+A（macOS）或
  Ctrl+A（Windows/Linux），系统 MUST 仅选中该代码块内的全部文本。
- **FR-003**: 在代码块内触发全选时，系统 MUST NOT 将选区扩展到该
  代码块之外的任何文档内容。
- **FR-004**: 代码块全选后的选区 MUST 支持标准操作
  ——复制、剪切、删除、以及"输入新内容替换选中内容"——且这些操作
  MUST 仅作用于被选中的代码文本。
- **FR-005**: 代码块内容为空时触发全选，系统 MUST NOT 产生错误或
  意外选中代码块之外的内容。
- **FR-006**: 当焦点位于代码块的辅助控件（如语言搜索输入框）而非
  代码文本本身时，全选快捷键 MUST 遵循该控件自身的默认行为，而不是
  被重定向到代码文本的全选逻辑。
- **FR-007**: 当光标位于任何代码块之外时，系统 MUST 保持现有的
  "全选整篇文档内容"行为不变。
- **FR-008**: 代码块全选后的视觉高亮样式 MUST 与文档中其他文本选区
  的高亮样式保持一致，不产生渲染异常（例如异常的高亮溢出区域）。

### Key Entities *(include if feature involves data)*

- **代码块 (Code Block)**：文档中的一种块级内容单元，包含一段纯文本
  代码及其语言标注；是本功能中"全选范围"的判定与限定对象。
- **选区 (Selection)**：当前被高亮选中的文本范围，可能限定在单个
  代码块内，也可能覆盖整篇文档——由光标当前所在位置决定其范围。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在代码块内只需按一次全选快捷键，即可一次性选中该
  代码块的全部代码，无需重复操作或手动拖选调整选区边界。
- **SC-002**: 无论代码块内容为空、单行还是多行，全选快捷键均能正常
  工作，不产生任何错误提示或应用崩溃。
- **SC-003**: 对至少 5 种不同语言/长度的代码块样本进行"全选后复制"
  测试，剪贴板内容与代码块原文逐字符一致的比例达到 100%。
- **SC-004**: 代码块之外的现有全选行为在本功能上线后保持 100% 不变
  （无回归）。

## Assumptions

- "Cmd+A" 泛指当前操作系统的标准全选快捷键：macOS 上为 Cmd+A，
  Windows/Linux 上为 Ctrl+A；两者均在本功能范围内，视为同一行为的
  跨平台等价形式。
- 全选范围只需支持"单级"语义：即代码块已被全选后再次按下快捷键，
  不需要像某些编辑器那样"逐级扩大"选区到整篇文档；保持简单的
  "光标在代码块内 → 只选代码块内容"规则即可满足当前需求。
- 本功能覆盖应用内所有承载代码块的编辑场景（包括主文档编辑器及其
  等价的分段/嵌入编辑场景），但不包括操作系统级的文本框（例如语言
  搜索输入框）——那些遵循各自输入控件的默认全选行为。
- 代码块处于"渲染预览"模式（源码被隐藏、仅显示可视化渲染结果）时，
  不属于本功能的适用范围，因为此时没有可编辑/可选中的代码文本可见。
